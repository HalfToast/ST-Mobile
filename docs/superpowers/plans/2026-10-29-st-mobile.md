# ST Mobile Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build an Android app that shows HalfToast's SillyTavern (on the tablet) without browser chrome, survives in the background, reloads fast, and has a native Control Center that does everything `stpanel` does over SSH, without changing anything on the tablet.

**Architecture:** There is a single-activity Kotlin/Compose app with four bottom tabs: Chat, Panel, Stats and Logs.

- **Chat** is one long-lived WebView that is never recreated on tab switches or configuration changes. A request interceptor serves SillyTavern's static assets from an app-side disk cache, namespaced by the server's git revision.
- **Background survival** comes from a `specialUse` foreground service.
- **Panel, Stats and Logs** talk to the tablet through a `RemoteShell` interface backed by sshj, with an app-generated key.
  - Actions call `stpanel`'s existing subcommands, with answers fed on stdin.
  - Dashboard, stats and whitelist data come from small read-only probe scripts, shipped as assets and run with `bash -s` / `python3 -`. They replicate stpanel's own commands.
  - Pure parsers turn probe output into state and are unit-tested.

**Tech Stack:** Kotlin 2.4.10, AGP 9.3.2, Gradle 9.7.1 (the versions that already build `~/Developer/mihon` on this Mac), Jetpack Compose (BOM 2026.07.01), androidx.webkit 1.17.0, sshj, JUnit 4, and JDK 17 (Temurin, installed).

**Spec:** `docs/superpowers/specs/2026-10-26-st-mobile-design.md`

## Global Constraints

- Nothing on the tablet changes: no edits to SillyTavern, config, the theme, the extensions or `stpanel`. The only write allowed is appending the app's public key to `~/.ssh/authorized_keys`.
- Nothing is injected into the SillyTavern page that changes its look or behavior. The only JS run is read-only readiness probing and the back-button Escape dispatch (Task 3).
- The SSH password is never stored. It is used once to install the key and then dropped.
- Defaults:
  - server URL `http://100.101.102.103:8000`
  - SSH host `100.101.102.103`
  - SSH port `8022` (overwritten by Task 1's finding)
  - ST user folder `default-user` (overwritten by Task 1's finding)
- SillyTavern on the tablet:
  - path `/data/data/com.termux/files/home/SillyTavern`
  - log `$ST_DIR/sillytavern.log`
  - access log `$ST_DIR/data/access.log`
  - backups `$ST_DIR/backups`
  - config `$ST_DIR/config.yaml`
- Package `dev.halftoast.stmobile`, app name "ST Mobile", `minSdk 29`, `targetSdk 36`, `compileSdk 36`.
- Test phone: an Android phone on Android 16 (SDK 36), adb serial `<serial>`, WebView 155. Every adb command uses `-s <serial>`.
- Dashboard refresh interval is 5 s while the Panel tab is visible, matching stpanel.
- Stop, Clean cache and Update need a confirmation dialog.
- The "running" notification is on by default and can be turned off in settings.
- Logging tag is `STMobile`.

## Review Focus

1. **The tablet is unreachable or SSH drops mid-action** (Tailscale off, tablet asleep). Expect a clear error within the timeout and buttons usable again, never a spinner forever. Tested in Task 9 (`PanelViewModelTest.shellFailureShowsErrorAndReenablesActions`).
2. **The tablet's host key changes** (Termux reinstalled). The app refuses to connect and shows a "host key changed" error with an explicit re-trust action. It never trusts silently. Tested in Task 6 (`HostKeyPolicyTest`).
3. **Rotation, dark mode toggle or keyboard show/hide.** The chat doesn't reload. Verified in Task 3, Step 6, which rotates via adb and checks that no second `ST_READY` appears.
4. **The WebView renderer process is killed by the OS.** The app recreates the WebView and reloads, and doesn't crash. Verified in Task 3, Step 6, via `chrome://kill`.
5. **SillyTavern is updated outside the app** (through HalfToast's SSH client), or `/version` is unreachable. The app never serves stale cached code: a revision change clears the cache, and an unknown revision bypasses it. Tested in Task 4 (`AssetCacheTest`).

### Task 4: Static asset cache

**Files:**

- Create: `chat/AssetCachePolicy.kt`, `chat/AssetCache.kt`

**Interfaces:**

- Consumes: `WebViewHolder.interceptor`.
- Produces:
  - `object AssetCachePolicy { fun shouldCache(method: String, path: String): Boolean }`
  - `class AssetCache(root: File)` with:
    - `fun setRevision(revision: String?)`. A new value wipes the cache; `null` disables caching.
    - `fun get(url: String): CachedAsset?`
    - `fun put(url: String, mime: String, encoding: String?, bytes: ByteArray)`
    - `fun clear()`
    - `val revision: String?`
  - `data class CachedAsset(mime: String, encoding: String?, bytes: ByteArray)`
  - `fun parseGitRevision(versionJson: String): String?`, which reads `gitRevision` from `/version`'s JSON.

Why this works: SillyTavern serves `public/` with `express.static` defaults (`src/server-main.js:242`), so every one of its many JS modules is revalidated on each cold load. Over Tailscale that is latency-bound. Serving unchanged assets locally removes those round trips.

- [ ] **Step 3: Implement the cache.**
  - **Policy:**
    - Cache GET requests only.
    - The path must start with `/lib/`, `/scripts/`, `/css/`, `/webfonts/`, `/img/` or `/locales/`, or equal `/lib.js`, `/script.js` or `/style.css`.
